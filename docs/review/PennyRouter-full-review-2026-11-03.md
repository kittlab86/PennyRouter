## Executive summary

PennyRouter's gateway, catalog, and routing code is extensively tested for happy-path, passthrough, privacy-field, header, and reload-last-good behaviour (see Appendix), but the merged review finds concentrated risk in four areas. First, the streaming and classifier paths defeat their own bounds: the upstream concurrency permit is dropped when SSE headers return, the classifier size cap is checked only after an unbounded download, and two quadratic loops (`truncate_input`, `split_model`) can hang a worker on admitted inputs. Second, sticky/session routing and fallback logic diverge from fresh-path ordering and throttling, so pinned sessions can receive arbitrary expensive models, re-hit throttled providers, or never reach the configured fallback. Third, the catalog pipeline can publish wrong or destructive data: a discount above 1 becomes permanently free, tiered pricing is ignored, unknown error rates rank as perfect, free-window expiry uses last-in-file instead of latest, and non-transactional sync can destroy prior endpoints on a mid-sync failure. Fourth, product and operations documentation overstates what ships — classifier/judge scope, privacy enforcement, freshness, p99 latency, 1M-token support, and virtual-menu readiness — while Compose silently drops the classifier, bounds, reload, and (in prod) catalog configuration that `cargo run` honours.

Security posture is mixed by design: the gateway is intentionally a public bring-your-own-key proxy with no gateway authentication, so the exploitable items are conditional on enabling `CLASSIFIER_API_KEY` / `GATEWAY_UI` or on network reachability, while key logging, header stripping, body caps, and secret handling were verified correct. No finding in this review was fixed; remediation is out of scope and no fix is invented here — gaps that the evidence cannot settle are named in Unresolved / Not Covered.

Counts after merging duplicates across scopes: Bugs B01–B18 (18), Critical errors C01–C08 (8), Product fit P01–P12 (12), Incomplete definitions D01–D10 (10), Improvements I01–I10 (10), Security S01–S11 (11). Verified-OK items are preserved in the Appendix, not counted as issues.

## Bugs

### B01 — [Verified][HIGH] Classifier default URL missing `/v1`, smart never classifies by default
`ClassifierConfig::from_env` reuses `OPENROUTER_BASE_URL` verbatim (`crates/gateway/src/lib.rs:204-207`), whose default is `https://openrouter.ai/api` (`crates/gateway/src/lib.rs:376-377`), but `call_classifier` builds `{base}/chat/completions` (`crates/gateway/src/lib.rs:1650`) while the gateway's own completion path builds `{base}/v1/...` via `strip_api_prefix` (`crates/gateway/src/lib.rs:1391-1396`). With only `CLASSIFIER_MODEL` set the leg 404s, maps to `Invalid` → fallback (`crates/gateway/src/lib.rs:1706-1713`), so smart never classifies in the documented default deployment. Source scope states tests use a bare-host mock base, masking it; completeness-critic notes that masking claim cites no test file/line (see Unresolved).

### B02 — [Verified][HIGH] Smart ids double-prefix on native alias
`routed_completion` strips `/api` only on the normal path (`crates/gateway/src/lib.rs:1391-1394`) but the smart early-return passes `uri.path_and_query` unstripped (`crates/gateway/src/lib.rs:1360-1366`) into `smart_completion` → `forward_upstream` `format!({base_url}{path})` (`crates/gateway/src/lib.rs:2461`). `POST /api/v1/chat/completions` with a smart id therefore forwards to `{base}/api/v1/chat/completions` (e.g. `.../api/api/v1/...`) and 404s.

### B03 — [Verified][HIGH] Cross-model sticky pick is arbitrary, not tier-ordered
`Pin` stores only provider + precision class (`crates/gateway/src/routing.rs:102-107`); `decide_ordered_virtual` builds candidates from `snapshot.models.values().flatten()` (HashMap order, `crates/gateway/src/routing.rs:73-76`, `crates/gateway/src/routing.rs:1417-1428`) and the sticky path returns `candidates.iter().find(provider+class)` (`crates/gateway/src/routing.rs:1470-1484`) instead of the fresh `min_by` cost/quality ordering (`crates/gateway/src/routing.rs:1486-1502`). Same find-pattern in `decide_lowest` (`crates/gateway/src/routing.rs:1574-1589`) and `decide_decision` (`crates/gateway/src/routing.rs:1682-1696`). After the first request a low/think/lowest session can be served any (including most expensive) model/tag of the pinned provider, changing after snapshot reloads.

### B04 — [Verified][MED] Fallback leg unreachable after a forwarded retry; retry 429s never throttled
`routed_completion` returns the retry response unconditionally (`crates/gateway/src/lib.rs:1463-1479`), so the free-fallback block below (`crates/gateway/src/lib.rs:1487-1539`), whose comment promises fallback after "the free attempt (and its single retry, if any)" failed (`crates/gateway/src/lib.rs:1482-1486`), only fires when no retry provider existed. When two free providers both 429/502 the configured `/fallback/<tier>` never serves. Same early-return shape in `routed_decisions` (`crates/gateway/src/lib.rs:1212-1241` vs `crates/gateway/src/lib.rs:1245-1299`). Retry-attempt 429s are never `note_throttled`, unlike first/fallback legs (`crates/gateway/src/lib.rs:1406-1425`, `crates/gateway/src/lib.rs:1516-1531`).

### B05 — [Verified][MED] `decide_free` sticky ignores throttle cool-down
The sticky branch returns the pinned provider after only allows/tool/free checks (`crates/gateway/src/routing.rs:1791-1819`) while the fresh branch applies `skip_throttled` (`crates/gateway/src/routing.rs:1830-1832`, doc `crates/gateway/src/routing.rs:654-656`). For legacy `openrouter/free` (`crates/gateway/src/routing.rs:876-889`) `lib.rs` creates `retry_body` only for `parse_virtual` ids (`crates/gateway/src/lib.rs:1371`, `crates/gateway/src/lib.rs:2053-2059`), so a just-429'd pinned free provider is re-hit and its 429 returned to the client despite fresh free alternatives.

### B06 — [Verified][LOW] Direct sticky checks only the ordered head against budget/tools
`decide_constrained` orders the pinned provider's offerings then tests only `.next()` for `budget_allows`/`tool_allows` (`crates/gateway/src/routing.rs:920-942`) whereas the fresh path filters by budget/tool before ordering (`crates/gateway/src/routing.rs:953-968`). If the head offering violates the cap but a second offering of the same provider+class fits, the pin is needlessly abandoned and the session re-routes/re-pins (possibly another provider) instead of keeping affinity on the fitting offering.

### B07 — [Verified][MEDIUM] Free-offer dedup downgrades permanent free to expiring
`rank.rs:422-429` skips any later endpoint whose (provider,tag) is already in offers; `rank.rs:439-459` checks static-zero (permanent, `valid_until None`) before the promo branch per endpoint in id order (`crates/catalog/src/rank.rs:422-429`, `crates/catalog/src/rank.rs:439-459`). If a promo-free row precedes a permanent-zero row for the same provider+tag, the permanent row is dropped; the gateway expires it at `crates/gateway/src/routing.rs:454` (`is_none_or(now<end)`). Order-dependent eligibility loss.

### B08 — [Verified][MEDIUM][Documented intent disputed] `free_until` is last-in-file, not latest expiry
`free_until` overwrites on each active `discount==1.0` window and returns the last `ends_at` (`crates/catalog/src/price.rs:190-201`). Overlapping free windows ending Apr then Feb publish Feb; the gateway stops free in Feb though the Apr window still covers (`crates/gateway/src/routing.rs:448-455`). Source scope frames this as union coverage should be max `ends_at`; catalog notes flag last-wins discount as documented intent where impact differs from intent — bug vs intent is unresolved (see Unresolved).

### B09 — [Verified][MEDIUM] Manifest counts unverified and can diverge from DB
`publish()` writes caller-supplied `model_count`/`endpoint_count` into the manifest without counting the DB (`crates/catalog/src/artifact.rs:69-98`); `verify()` checks only sha256 (`crates/catalog/src/artifact.rs:103-111`). Callers pass the sync Summary (`crates/catalog/src/main.rs:151-157`) which counts array iterations/inserts (`crates/catalog/src/sync.rs:71`, `crates/catalog/src/sync.rs:116`): duplicate model ids (`INSERT OR REPLACE`, `crates/catalog/src/sync.rs:64-70`) or duplicate endpoint bodies (delete-then-insert, `crates/catalog/src/sync.rs:85`) inflate counts vs `Catalog::counts()` (`crates/catalog/src/store.rs:277-287`), yet the artifact still verifies and catalog-ui displays manifest counts (`crates/catalog-ui/src/main.rs:140-148`).

### B10 — [Verified][MEDIUM] Tiered pricing ignored
`extract_price` reads only `pricing.prompt/completion/input_cache_read/input_cache_write` (`crates/catalog/src/process.rs:56-63`, `crates/catalog/src/process.rs:35-38`). A fixture endpoint carries `pricing.overrides[{min_prompt_tokens:272000, prompt:2x base}]` (`crates/catalog/tests/fixtures/endpoints/openai__gpt-6.1-terra-pro.json:1`, single-line JSON, so the override cannot be located more precisely). Long-context (>=272k; catalog supports 1M context in fixture) cost is underpriced ~2x in every rank orientation.

### B11 — [Verified][MEDIUM] Sync never prunes removed models
Sync only `INSERT OR REPLACE`s models present (`crates/catalog/src/sync.rs:53-72`) and deletes endpoints only for models present in the endpoints slice (`crates/catalog/src/sync.rs:85`). Re-sync into an existing DB keeps models/endpoints dropped or fetch-skipped upstream indefinitely, and `rank_catalog` (`crates/catalog/src/rank.rs:348-364`, built from endpoints) keeps ranking them. The fresh-DB binary (`crates/catalog/src/main.rs:134-135`) masks it; library resync does not mirror source.

### B12 — [Verified][MEDIUM] Process swallows model-lookup errors, aborts on endpoint errors asymmetrically
One corrupt endpoint payload `?` aborts the entire run (`crates/catalog/src/process.rs:24`), while `get_model().ok().flatten()` + JSON `.ok()` silently caches `None` per model (`crates/catalog/src/process.rs:25-31`), so a DB/parse failure yields `supports_decisions=None` (unknown) for all that model's endpoints instead of failing. Silent decision-tier misrouting.

### B13 — [Verified][LOW-MEDIUM] Read-only opens skip schema validation
`open_read_only` sets no pragmas/checks and never init/migrates (`crates/catalog/src/store.rs:107-110`); `catalog-rank.rs:75` uses it directly (`crates/catalog/src/bin/catalog-rank.rs:75`). A v1 DB (missing indexed columns) fails opaquely as sqlite no-such-column from the `ENDPOINT_COLS` query (`crates/catalog/src/store.rs:64-67`, `crates/catalog/src/store.rs:268-274`) instead of a Schema version error (`crates/catalog/src/store.rs:130-134`, only in migrate). Migrate also only adds missing columns by name (`crates/catalog/src/store.rs:136-141`), never validates existing column type.

### B14 — [Verified][LOW] Catalog-ui link and price display bugs
`esc()` escapes HTML (`crates/catalog-ui/src/main.rs:28-33`) but `href` at `crates/catalog-ui/src/main.rs:173-177` inserts the raw model id into `/endpoints?model={}` with no percent-encoding; ids containing `&`, `+`, `%`, `#` break the filter parsed at `crates/catalog-ui/src/main.rs:196`. ### B15 — [Verified][LOW] Endpoints-dir id mapping is lossy

## Critical errors

Critical errors are crash, hang, OOM, data-loss, or bound-bypass failures. Severity quoted per source; the SSE item carries four different severities across scopes (CRITICAL / HIGH / MEDIUM) for one root cause — merged here once.

### C01 — [Verified][CRITICAL in resilience; HIGH gateway; MEDIUM security/product] SSE concurrency cap released at headers
`forward_upstream` owns `_permit: UpstreamPermit` (`crates/gateway/src/lib.rs:2452-2455`) but on `text/event-stream` returns `stream_response(status, upstream, idle, metrics)` without moving the permit into the stream (`crates/gateway/src/lib.rs:2505-2512`). `stream_response` state holds only `(upstream, metrics, in-flight guard, failed)` (`crates/gateway/src/lib.rs:2592-2594`), so the semaphore slot drops when `forward_upstream` returns while the SSE body is still flowing, defeating the at-most-`max_upstream` bound (`crates/gateway/src/lib.rs:148-155`; promise `crates/gateway/src/lib.rs:44-48`, `docs/performance.md:36`). Many trickling SSE clients can exceed connections/memory, bounded only by per-chunk idle (`crates/gateway/src/lib.rs:2598`). Product-fit B-5's wording that a slow trickle "can hold upstream slot (`lib.rs:2591` guard held for body lifetime)" conflates the metrics in-flight guard with the `UpstreamPermit`; code verifies only the metrics guard is held. Existing resilience tests use a non-streaming slow JSON mock (`crates/gateway/tests/resilience.rs:54-64`), not SSE under `max_upstream=1`. Stream also has no aggregate cap (buffered-only 16MiB bound, `crates/gateway/src/lib.rs:83-86`; `stream_response` enforces per-chunk idle only, `crates/gateway/src/lib.rs:2584-2634`). Graceful shutdown can therefore drain forever: `with_graceful_shutdown` has only Ctrl-C/SIGTERM and no drain deadline/force-close (`crates/gateway/src/main.rs:26-29`, `crates/gateway/src/main.rs:34-53`), and SSE streams end only on upstream idle/error (`crates/gateway/src/lib.rs:2598-2621`).

### C02 — [Verified][HIGH resilience; MED gateway; LOW-MEDIUM security] Classifier size bound checked after unbounded download
`call_classifier` collects `response.bytes().await` with no cap inside the timeout closure (`crates/gateway/src/lib.rs:1658-1664`) and only afterwards checks `bytes.len() > MAX_CLASSIFIER_BYTES` (`crates/gateway/src/lib.rs:1715-1721`; bound intent `crates/gateway/src/lib.rs:188-190`, `MAX_CLASSIFIER_BYTES=64KiB`). `[Inference]` A fast/hostile configured classifier upstream can force multi-GB allocation in 8s despite the stated 64KiB bound. `read_capped_upstream` shows the correct capped pattern (`crates/gateway/src/lib.rs:2530-2562`, chunk-capped 16MB path `crates/gateway/src/lib.rs:2530-2570`).

### C03 — [Verified][HIGH] Discount > 1 becomes permanently free
`extract_discount` checks only finite && `>=0.0`, no `<=1.0` (`crates/catalog/src/process.rs:94-101`); promos reject >1 at `crates/catalog/src/price.rs:145-149`. A `promo_discount=2.0` is stored, `effective_cost` clamps discount to 1.0 (`crates/catalog/src/price.rs:75`) -> cost 0, and `rank.rs:431-444` publishes a permanent `FreeOffer` (`crates/catalog/src/rank.rs:431-444`). A bad/imported catalog discount silently makes a paid endpoint free.

### C04 — [Verified][HIGH] Fetch extra-model merge unvalidated; one bad extra aborts whole sync
Fetch only checks `extra.get("data")` exists (comment at `crates/catalog/src/fetch.rs:62-63` claims both model+endpoints), never checks `data.endpoints` array nor `data.id == requested id`, then pushes the pair (`crates/catalog/src/fetch.rs:60-81`). Sync then requires `data.endpoints` (`crates/catalog/src/sync.rs:77-84`) and keys models by payload id while endpoints are keyed by requested id (`crates/catalog/src/sync.rs:54-58`, `crates/catalog/src/sync.rs:75`, `crates/catalog/src/sync.rs:111`) -> one malformed/mismatched extra aborts the whole sync (FK at `crates/catalog/src/store.rs:100`) instead of landing in skipped. Same for any HTTP-200 malformed endpoints body (fetch checks status only, `crates/catalog/src/fetch.rs:95-102`).

### C05 — [Verified][HIGH] Non-transactional sync destroys prior data on failure
`delete_endpoints_for` runs before inserts (`crates/catalog/src/sync.rs:85`); a `provider_name` error at `crates/catalog/src/sync.rs:90-94` aborts after delete + partial inserts (`crates/catalog/src/sync.rs:95-115`). The store has no transaction API; each execute autocommits (e.g. `crates/catalog/src/store.rs:187-193`, `crates/catalog/src/store.rs:177-184`). Re-sync into an existing DB (gather resync path) loses that model's previous endpoints; `run_processing`/`run_judging_selected` likewise half-update in place (`crates/catalog/src/process.rs:32-46`, `crates/catalog/src/judge.rs:254-263`). A fresh work DB in catalog `main` (`crates/catalog/src/main.rs:134-135`) mitigates publish, not library/in-place use. `[Inference]` Data loss on failure was not dynamically reproduced.

### C06 — [Verified][MED][Inference: hang] Classifier truncation is quadratic and blocks a worker holding a slot
`truncate_input` loops `items.remove(0)` while re-cloning and re-serializing the whole array each iteration via `chars(&Value::Array(items.clone()))` (`crates/gateway/src/classifier.rs:54-71`; resilience cites `crates/gateway/src/classifier.rs:54-67`, plus `extract_input` clones messages `crates/gateway/src/classifier.rs:31-38` and `build_request` serializes the envelope again `crates/gateway/src/classifier.rs:100-108`). A smart body with ~1e6 tiny messages (within the 4MiB cap, `crates/gateway/src/lib.rs:37-39`) makes classification effectively hang on the async worker while `smart_completion` holds the admission permit (`crates/gateway/src/lib.rs:1324-1330`, `crates/gateway/src/lib.rs:1760-1768`) and burns the 1-CPU budget before the upstream leg.

### C07 — [Verified][MED][Inference: hang] `split_model` is quadratic on slash-heavy model ids
`split_model` `rsplit_once`-loops over every `/` and HashMap-hashes the shrinking head prefix each iteration (`crates/gateway/src/routing.rs:3442-3460`), and `route_inner` + `decide_constrained` repeat it (`crates/gateway/src/routing.rs:1970-1977`, `crates/gateway/src/routing.rs:890-891`). A ~4MiB model string of `a/a/a/...` (admitted by `crates/gateway/src/lib.rs:37-39`) causes O(segments x length) hashing/CPU hang on an unauthenticated request whenever a router is configured.

### C08 — [Verified][LOW] `spawn_reload_task` panics on the documented disable value; severity/rubric gap
`reload_interval_from_env` documents 0 disables (`crates/gateway/src/lib.rs:447-455`) but `spawn_reload_task` passes the duration straight to `tokio::time::interval` (`crates/gateway/src/lib.rs:464-467`), which panics on a zero period; the binary is saved only by main's `is_zero` guard (`crates/gateway/src/main.rs:19-24`), leaving a public API footgun for embedders/tests. Definitions notes Compose drops `RELOAD_INTERVAL_SECS` entirely, so this panic is unreachable in Docker — the deployment precondition was never reconciled across scopes. This item also exemplifies the cross-scope severity problem: resilience alone uses CRITICAL, catalog invents LOW-MEDIUM, security mixes HIGH-exploitable/MEDIUM-hardening/VERIFIED-OK in one list, and product-fit rates doc staleness `[High]` equal to runtime privacy `[High]`, with conditional preconditions not normalized against unconditional HIGHs. No shared rubric exists (see Unresolved).

## Improvements

Improvements are bounded-cost, correctness-adjacent, or maintainability items below bug severity. No fix is prescribed beyond naming the gap the evidence states.

### I01 — [Verified][HIGH resilience] Memory envelope vs 1GB target
Request cap 4,000,000B (`crates/gateway/src/lib.rs:37-39`), buffered upstream cap 16MiB (`crates/gateway/src/lib.rs:83-86`), defaults allow 64 upstream (`crates/gateway/src/lib.rs:47-48`). The virtual buffered flow also keeps a `retry_body` clone (`crates/gateway/src/lib.rs:1371`) plus a `fallback_body` clone (`crates/gateway/src/lib.rs:1445`) while awaiting a 16MiB-capped response (`crates/gateway/src/lib.rs:2513-2517`), before counting full JSON `Value` parses (`crates/gateway/src/routing.rs:1937-1940`). `[Inference]` 64 concurrent virtual requests can exceed the ~1GB budget in `docs/performance.md:5-12` even without classifier abuse.

### I02 — [Verified][MEDIUM] Queue wait has no deadline
`Timeouts` has connect/first/idle/total/upload fields but no queue timeout (`crates/gateway/src/lib.rs:60-80`); `acquire_upstream_slot` waits on `upstream_slots.acquire_owned().await` indefinitely after taking a queue slot (`crates/gateway/src/lib.rs:2297-2313`), and retry/fallback legs re-enter it (e.g. `crates/gateway/src/lib.rs:1453-1459`, `crates/gateway/src/lib.rs:1498-1504`). Source scope suggests a bounded queue wait returning 503 — recorded as the scope's suggestion, not adopted as a decided fix here.

### I03 — [Verified][MEDIUM] Reload blocks an async worker; snapshot/ranking not jointly atomic
`spawn_reload_task` synchronously calls `router.reload()` on a Tokio task (`crates/gateway/src/lib.rs:460-479`); `Router::reload` does disk/catalog `load_snapshot` then `swap_snapshot` before discover/swap ranking (`crates/gateway/src/routing.rs:785-792`). Heavy reload can stall a 1-CPU runtime and requests can observe a new snapshot with old ranking despite `crates/gateway/src/lib.rs:457-459` "atomically publishes"; ranking best-effort is documented at `crates/gateway/src/routing.rs:781-784`. Source scope suggests `spawn_blocking` and a combined `Arc` snapshot+ranking swap — recorded as suggestion only. This coexists with the verified-OK "reload keeps last good snapshot on load failure before swap" (`crates/gateway/src/routing.rs:785-792`; `crates/gateway/src/lib.rs:471-476`): last-good retention and joint atomicity are different properties.

### I04 — [Verified][MEDIUM] Hot-path repeated full-body parses/clones
`routed_completion` calls `raw_model` twice (`crates/gateway/src/lib.rs:1342`, `crates/gateway/src/lib.rs:1351`; `raw_model` does `serde_json::from_slice::<Value>` at `crates/gateway/src/lib.rs:2382-2388`), `is_virtual_request` parses again (`crates/gateway/src/lib.rs:2053-2059`), `route_inner` parses again (`crates/gateway/src/routing.rs:1937-1940`), and fallback eagerly clones body + parses `retry_body` even before knowing retryability (`crates/gateway/src/lib.rs:1436-1445`). This conflicts with `docs/performance.md:20-21` parse/one-lookup/forward and multiplies CPU/allocation for near-4MB bodies.

### I05 — [Verified][MEDIUM] Lock-held catalog scans
Virtual/free decisions collect multiple whole-catalog `Vec`s under the snapshot read lock (`crates/gateway/src/routing.rs:1417-1466`; `decide_free` also clones free Offerings at `crates/gateway/src/routing.rs:1822`) and may take the sessions write via `store_pin` while the snapshot guard is still in scope (`crates/gateway/src/routing.rs:1049-1066`, `crates/gateway/src/routing.rs:1507-1515`). `[Inference]` No cross-lock deadlock was verified, but reload `swap_snapshot` write (`crates/gateway/src/routing.rs:796-798`) can be delayed/starved under continuous virtual traffic. Source scope prefers `Arc` snapshot handles dropped before session/throttle locks.

### I06 — [Verified][LOW] Throttle cap contract broken; sessions correctly capped
`MAX_THROTTLES=4096` (`crates/gateway/src/routing.rs:423-425`), but `note_throttled` only retains expired entries when full and then unconditionally inserts (`crates/gateway/src/routing.rs:658-665`); if none expired it grows past the cap.
